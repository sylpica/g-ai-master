# データ保護とスキーマ移行 — g-ai-master

実施日：2026-11-11／対象：src/lib/storage.ts、src/types.ts

## 1. 変更の要点

- 保存キー `g-ai-master:state:v1` は据え置き（既存ユーザーの記録を同じ場所で読み続ける）。中身の `schemaVersion` で版を管理し、v1→v2 へ移行する。
- 退避キー `g-ai-master:state:backup` を新設。移行前・インポート適用前の状態を原文のまま退避する。

## 2. 読み込み（parseState）の新契約

`parseState` は状態そのものではなく `{ state, status, notes }` を返す。

| status | 意味 | 画面の扱い |
|---|---|---|
| ok | 正常な v2 | そのまま利用 |
| empty | 保存なし | 既定状態で開始（異常ではない） |
| migrated | v1 を v2 へ無損失移行 | 移行前に原文を退避キーへ保存してから利用 |
| corrupt | JSON破損または致命的形状の破損 | **既定状態で自動上書きしない**。自動保存を止め、ダウンロード／部分復旧／初期状態で始める、の選択肢を提示 |
| unsupported | 未知の新しいスキーマ版 | 同上（旧版アプリが新データを壊さないため） |

致命的形状（hasFatalShape）とレコード単位の妥当性（isValidAnswer / isValidReviewCard / isValidExam / isValidCardReview）を分離した。配列の中の個別レコードの破損は、そのレコードだけを除外して notes に記録し、全体は読み込む。設定値の範囲外は normalizeSettings で既定値に戻す（致命扱いしない）。

## 3. v1→v2 移行（migrateV1toV2）

- 追加されるのは新フィールドのみ：`cardReview: {}`、`cardDirection: 'term-first'`、`practicePrefs: { questionShuffle: true, choiceShuffle: true }`。
- 既存の answers / exams / bookmarks / review / lessonsDone / settings / dailyGoalMin は値を変えずに引き継ぐ。
- 無損失の証明：`tests/fixtures/state-v1.json`（回答2件・模試1件・ブックマーク2件・復習1件・ダークテーマ・目標30分）をフィクスチャとして保持し、移行後に全レコードが保持されること、および移行後の export→parse 往復が同一になることを単体テストで担保する（tests/unit/overhaul.test.ts）。

## 4. インポート（validateImport）の厳格化

旧仕様は検証なしに置き換えており、壊れたファイルで記録が消えた（P0-1）。新仕様は次の順序を必須とする。

1. ファイルサイズ上限 5MB。
2. JSONとして解釈可能で、オブジェクトであること。
3. スキーマ版が 1 または 2 であること（未知の版は拒否）。
4. 致命的形状チェック（answers が配列でない等は拒否）。
5. 実在ID照合：回答・模試・ブックマーク・単語帳復習の参照先が、現在のコンテンツ（問題・カード）に実在すること。不一致は拒否理由として列挙。
6. プレビュー：現在と取り込み後の件数比較表（回答／模試／ブックマーク／学習済み教材／復習予定／単語帳の復習予定）を表示。
7. ユーザーの明示確認の後にだけ反映（原子的反映）。適用直前に現在の状態を退避キーへ保存する。

検証に失敗した場合は現在の記録を変更せず、理由を role=alert で表示する。

## 5. 部分復旧（salvageState）

corrupt 時にユーザーが選べる復旧経路。正常に読めるトップレベルフィールドだけを残し、壊れた部分は既定値にする。全体を捨てるか全部残すかの二択にしない。

## 6. 回帰テスト

- P0-1 再現入力（answers が文字列）が拒否されること。
- P0-2 相当（設定だけ壊れた状態）が corrupt として検出され、自動上書きされないこと。
- v1 フィクスチャの移行無損失と往復同一性。
- 未知スキーマ版の拒否、実在しない問題IDを含む記録の拒否。


## 追補：2026-11-12（2026.11.14）

保存スキーマの変更はない（schemaVersion 据え置き）。模試提出時に回答が `answers`・`review` へ記録されるようになったため、2026.11.14 以降に提出した模試から分析へ反映される。それ以前に提出済みの模試は `exams` に回答が残っており、分析の「模擬試験の履歴」（セッション単位で再計算）には表示される。一方、模試正答率・到達判定・分野別は `answers` から集計するため、過去の模試分は含まれない。`answers` への遡及追加は行っていない（保存済みの記録を無断で書き換えず、初見判定の時系列を後から変えないため）。
