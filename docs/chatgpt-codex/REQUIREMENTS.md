# 要件定義：AI総合マスター 第4モード「ChatGPT・Codex」

決定：ユーザー（2026-11-19）。単独アプリではなく AI総合マスター（sylpica/g-ai-master）の追加モードとする。開発担当は Codex。本書式は要件の正本であり、開発指示は DEV_PROMPT.md。

## 1. モードの位置づけ

- モードキー：`'chatgpt'`（`src/types.ts` の Mode に追加）。表示名：「ChatGPT・Codex」。
- 型：**教養型**。模試メニューと到達度（合格可能性のような表示）は出さない。得点換算・確率は表示しない（全モード共通の絶対条件）。
- 画面：**標準ビュー流用**。ダッシュボード／シラバス／教材／演習（問題）／単語帳／設定／記録・分析の既存画面をそのまま使う。教養モード専用のタブビュー（LiteracyView）は使わない。
  - 実装上の注意：現行の `isExamMode = m !== 'literacy'` は「模試の有無」と「教材の遷移先」を兼ねている。新モードは「教材は標準の lessons ルート」「模試なし・到達度なし」が正しい姿なので、この分岐を役割ごとに分けて実装すること（例：模試・到達度の表示可否と、教材ルートの選択を別関数にする）。AI教養モードの既存挙動は一切変えないこと。
- モード切替ボタンの並び：G検定取得 → 生成AIパスポート → AI教養 → ChatGPT・Codex（4番目）。設定の「起動時に最初に開くモード」にも選択肢を追加する。既定は従来どおり 'g' のまま。
- モードを切り替えても学習状態（回答・教材完了・カード評価・ブックマーク等）は失われないこと（既存の保存構造をそのまま使う。保存キーは変更しない）。

## 2. コンテンツ（土台は STRUCTURE.md と通読メモ2件）

土台資料：書籍『できるChatGPT Work&Codex 仕事を自走させるAIエージェント実践術』（インプレス）の章・レッスン構造と、付属の練習用プロンプト集。教材本文は書籍の転載ではなく、構造と要点に基づく自作の解説として書くこと（手順の丸写し・長文引用はしない。プロンプト例は要点を再構成した短い例示に留める）。

### 2.1 シラバス：8件
- STRUCTURE.md の8章を SyllabusNode として登録する（id: cx-ch1〜cx-ch8、area は基本編／活用編、chapter は「第N章」、title は章タイトル、order は章順）。

### 2.2 教材（レッスン）：56件（最重点＝充実させること）
- 全56レッスンを教材化する（id: les-cx-01〜les-cx-56、syllabusId は対応する章）。
- 各教材の必須構成（既存モードの Lesson 型に沿う）：
  - basic（基礎解説）：3段落以上。レッスンの目的と全体像、中心概念、覚えるべき型や手順の骨格。
  - detail（詳細解説）：4段落以上。手順の考え方、判断のポイント、実践プロンプトの型（STRUCTURE.md の共通パターン参照）を、そのレッスン固有の題材で具体化する段落を必ず含める。
  - keyPoints：3点以上。pitfalls（注意点）：2点以上（例：推測で補わない、元ファイルを変更しない、重要な操作は自分で確認する、など題材に即したもの）。
  - 図表（visualIds）：構造図表を各教材2点以上（後述 2.5）。
  - sources：出典を必ず付ける。書籍はタイトルと出版社を明記し、URL出典は OpenAI 公式（help.openai.com、openai.com、developers.openai.com 等）の中で実在確認（到達確認）できたページを使う。確認できないURLは使わない。
  - 第4章・L22・L23・L38・L52 など有料版（ChatGPT Plus）でのみ使える機能を扱う教材には、その旨を advancedNote か本文で明示する。
- 教材の文章は、既存モードの教材と同じ密度・文体（要点→基礎→詳細→注意点）で書く。水増しは禁止。56件すべてに固有の内容を持たせること（共通文の使い回しで件数だけ揃えない）。

### 2.3 実践演習（Exercise）：40件
- プロンプトが存在する40レッスン（STRUCTURE.md の「プロンプト：Lnn」）について、既存の Exercise 型で実践演習を作り、対応する教材ページの下部に表示する。
- 各演習の構成：background（題材の背景）、goal（作る完成物）、constraints（使う資料の限定・禁止事項などプロンプトの要点から）、steps（進め方の手順）、rubric（自己評価の観点）、modelThinking（考え方の型）、failureExample（失敗例）、improvementExample（改善例）。
- 元データは docs/chatgpt-codex/prompts/Lnn.txt と reading-prompts.md の要約。要約を土台に自作し、プロンプト全文の転載はしない。

### 2.4 演習問題：112問
- 各レッスン2問、計112問（id: q-cx-001〜）。既存の Question 型に沿い、stem／choices（4択）／answer／basic（基本解説）／detail（詳細解説）／choiceReasons（選択肢別の理由）／sources を完備する。
- 内容は教材の理解確認（概念・手順の判断・安全な任せ方）に寄せる。正答位置は 1〜4 に均等に分散させる。出典には書籍と、確認できた OpenAI 公式ページを含める。

### 2.5 図表（構造図表）：各教材2点以上
- 既存の lessonVisuals の仕組み（LESSON_VISUALS）に、新モード用の図表データを追加する（ファイル分割は実装側の判断でよい）。
- 図表は「その教材の内容そのもの」を表すものにする（例：プロンプトの6要素、計画→承認→実行→確認のフロー、サンドボックスの範囲、サブエージェントの並行処理、第5章の分析の型、第8章のGitの記録と巻き戻し）。共通テンプレートの使い回しだけで済ませず、各教材に固有の図表を最低1点入れる。
- 生成AIによるイメージ図（イラスト）は今回の範囲外とする（次フェーズで別途扱う）。

### 2.6 単語帳：90枚
- 書籍の用語集74語を全てカード化する（定義は書籍の表現を写さず、教材の文脈で自作する）。
- 各章の要点カードを章ごとに2枚、計16枚を加える（id は fc-cx- 連番で一括管理）。
- 既存の Flashcard 型に沿い、term／definition／example／confusion（混同注意）／sources を持たせる。

### 2.7 対象外（今回やらないこと）
- 要点まとめPDFの新モード分（次フェーズ）。
- 生成イラスト（次フェーズ）。
- ニュースタブへの追加（教養ニュースは凍結中の方針。新モードにニュース機能は付けない）。
- 既存3モードのコンテンツ・挙動の変更（共通部の分岐整理を除く）。

## 3. 品質・運用条件（全モード共通の絶対条件を含む）

- 完全無料：ログイン・有料API・外部DBなし。外部素材の同梱はしない（練習用ファイル自体はアプリに含めない。演習は題材の説明と手順で完結させる）。
- UIルール（全学習アプリ共通）：スクロールは最小化し主要コンテンツは一画面に収める／文字の切れ・見切れ・はみ出しを作らない（375px幅を含む全幅で実表示確認）／免責や説明文は画面の下部に置く／「実質縦書き」崩れ（flex行でラベルが1文字幅まで潰れる）を作らない。図表はラベルと本文を縦積みの箱にし、狭幅では箱ごと折り返す。
- 開発プロンプトの恒常文：「不要なセカンダリラベルや説明を避ける。レイアウト自体に説明させる。」
- バージョン同期：contentVersion を 2026.11.16 に上げ、3点（public/data/manifest.json、src/lib/update.ts の BUNDLED_CONTENT_VERSION、src/lib/storage.ts）を同時更新する。
- テスト：単体テストに新モードのデータ整合性（件数 8／56／40／112／90、ID一意性、出典の存在、図表2点以上、問題の正答・理由の完備）を追加する。E2Eに「モード切替→ダッシュボード表示→教材ページ（演習セクション含む）表示→演習セッション→単語帳→リロード後のモード保持→既存モードの回帰」を追加する。既存テスト全件と合わせて全通過、ビルド成功が完了条件。
- 配信：Codex 側はブランチ＋PR で main へ提出する（gh-pages への公開反映は Muse 側で独立検証後に行う）。PR には変更概要・テスト結果・書き込みコール数を含めること。

## 4. 受け入れ基準（Muse 側の独立検証で確認する）

1. 4モード切替が往復でき、既存3モードの表示・記録が従来どおりであること。
2. 新モードのダッシュボードに模試・到達度が出ないこと。教材・演習・単語帳が標準ビューで使えること。
3. 教材56件・演習40件・問題112問・カード90枚・図表（各教材2点以上）が実データとして存在し、単体テストで担保されていること。
4. 問題の正答と解説が教材内容と矛盾しないこと（Muse 側でブラインド再解答を含む多角検証を行う）。
5. 375px幅で新モードの主要画面に文字の切れ・実質縦書き崩れがないこと。
