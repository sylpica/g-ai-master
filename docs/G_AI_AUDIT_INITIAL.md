## 3. 既知指摘の再検証（全12件）

### P0（データ損失・判定の信頼性）

- **P0-1 インポートで記録が消える：再現**。`{"schemaVersion":1,"answers":"broken","settings":{}}` を設定画面から読み込むと、確認ダイアログが「0件で置き換えますか」と表示し、承認で既存の回答1件が消失した（localStorage の answers 1→0 を実測）。検証なしに parseState の既定値をそのまま反映していたことが原因。
- **P0-2 読み込み異常で自動上書き：再現**。settings だけが壊れた正常データ相当をシードすると、退避（:backup キー）も警告（role=alert 0件）もなく初期値で自動上書きされ、回答・ブックマークが全消失した。
- **P0-3 回答記録の競合：コードで確認**（実ブラウザでは setState updater の同期実行により再現せず）。recordAnswer が非同期境界をまたいで古い state を参照しうる構造だった。
- **P0-4 シャッフルの偏り：実測**。現行 LCG シャッフルの先頭分布は 300要素×10,000シードで最小0回・最大762回（期待平均33.3回）。実用上「シャッフル」と呼べない偏り。

### P1（主要機能の欠落・誤判定）

- **P1-1 復習画面に保存ボタンなし：再現**（コードでも onBookmark が復習画面へ伝達されていないことを確認）。
- **P1-2 到達判定の誤り：コードで確認**。analysis.ts の到達判定が `exams.length>=30`（提出済みセッション数ではなく回答レコード数相当）を使っており、模試1回・初見1問正解でも到達扱いになり得た。
- **P1-3 演習中リロードでホームに戻る：再現**（ルーティングがメモリ内 state のみで、URLに画面情報がなかった）。
- **P1-4 AI教養の教材一覧に検索なし：再現**。
- **P1-5 模試の選択肢順が固定され得る／二重提出のガード不足：コードで確認**。
