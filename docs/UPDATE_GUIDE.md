# 教材更新の説明

## 利用者向け更新（アプリ内のボタン）

- 「設定・更新」画面のボタンで、公開済みの教材マニフェスト（`data/manifest.json`）を取得し、現在の教材バージョンと比較します。
- 新しい版がある場合は、その旨と公開日が表示されます。実際の教材の差し替えは、アプリ本体（新しい版）が公開された後にページを再読み込みすることで反映されます。
- 更新に失敗した場合（通信エラー、マニフェストの形式不正など）は、動作していた旧教材がそのまま維持されます。
- 教材更新で学習記録が初期化されることはありません。

## 管理者向け更新（GitHub上で行う作業）

公開アプリからGitHubへ書き込むことはできません。教材の更新は次の手順で行います。

1. 教材・問題データを編集する（出典・取得日・検証日を必ず更新する）
2. `npm test` でデータ検証（シラバス対応、重複、必須項目、出典URL形式）を通過させる
3. 意味的な正確性を一次資料と照合し、レビューする（AIの自己判定だけで「検証済み」にしない）
4. `public/data/manifest.json` の `contentVersion` と `publishedAt` を更新する
5. 節目単位でまとめてGitHubへ配信し（push-files 1回＋必要ならPR・マージ各1回）、CI通過と公開サイトの反映を確認する
6. 誤りが見つかった問題は `status` を `suspended` にして通常演習から除外し、影響を記録する

## 情報源の優先順位

政府・公的機関・公式規格 ＞ 開発元の一次資料 ＞ 原著論文・学術資料 ＞ 独立した技術評価 ＞ 専門メディア ＞ SNS・コミュニティ（発見の手がかりにのみ使う）

プレプリントは査読済み論文と区別し、企業の性能主張は独立評価と照合する。
